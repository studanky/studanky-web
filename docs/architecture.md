# Architecture

This document describes the stable boundaries of the Studánky web frontend.
It is intentionally organized by subsystem rather than as a catalog of every
React component.

## Route families

| Public route | Implementation | Responsibility |
| --- | --- | --- |
| `/{locale}` | `src/app/[locale]/` | Localized landing page, legal pages, metadata, and Open Graph content. Supported content URLs are always prefixed, currently `/cs` and `/en`. |
| `/s/{documentId}` | `src/app/s/[documentId]/` | Unprefixed shared-spring fallback for native deep links. It resolves request language, fetches a Strapi preview, and renders non-indexable metadata and UI. |
| `/download` | `src/app/download/route.ts` | Stable store-agnostic download URL. It redirects by platform or falls back to the localized landing-page download section. |
| `/.well-known/*` | `src/app/.well-known/` | JSON association files for iOS Universal Links and Android App Links. These routes must never be locale-prefixed or redirected. |
| `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest` | Metadata files in `src/app/` | Search-engine and install metadata generated by Next.js file conventions. |

`src/proxy.ts` applies locale redirects only to localizable page routes. The
deep-link, download, association, metadata, framework, API, and static-asset
paths are excluded by its matcher. Keep `proxy.ts` beside `src/app/`; this is
the Next.js 16 file convention used by this project.

## Server and client boundaries

Server Components are the default. They load dictionaries, build metadata, and
fetch backend data without exposing environment variables or complete message
catalogs to the browser.

Use a Client Component only when the subtree needs browser state, effects, or
event handling. Current client islands cover navigation, reveal effects, the
newsletter form, coordinate copying, dialogs, and the dismissible Android
banner. Values crossing from a Server Component to a Client Component must be
serializable plain data; Server Actions are the supported function exception.

Server-only integration code is marked explicitly:

- `src/lib/springs.ts` owns Spring Preview fetching and normalization.
- `src/app/actions/newsletter.ts` owns the newsletter mutation.

Do not add an internal Route Handler merely to call it from a Server Component.
Read data directly in the Server Component layer and use Server Actions for
mutations initiated by this UI. Route Handlers in this project exist for public
HTTP behavior such as association documents and redirects.

## Source ownership

| Location | Owns |
| --- | --- |
| `src/app/` | URL structure, layouts, page composition, metadata, route handlers, and Server Actions. |
| `src/components/landing/` | Marketing-page sections and their composition. |
| `src/components/app-links/` | Shared-spring and native-app promotion UI. |
| `src/components/legal/` | Rendering of structured legal documents. |
| `src/components/ui/` | Reusable shadcn/ui primitives. These remain implementation-level building blocks. |
| `src/components/layout/`, `icons/`, `mock/` | Small shared layout, icon, and presentation helpers. |
| `src/config/` | Locale-independent structural data such as URLs, store identifiers, legal metadata, and asset dimensions. |
| `src/i18n/` | Locale types, language negotiation, dictionary loading, and template formatting. |
| `src/lib/` | Shared domain and server utilities without route-level presentation. |
| `src/types/` | Cross-subsystem TypeScript contracts. |
| `messages/` | Localized user-facing copy. |
| `public/` | Static assets served from the site root. |

Prefer the narrowest existing subsystem. Create a new subsystem directory only
when a feature has a distinct responsibility and more than one collaborating
module; do not create per-component README files.

## Data flows

### Localized pages

The locale segment is validated against `src/i18n/config.ts`. A Server
Component loads the matching typed catalog and passes only the required copy to
interactive client islands. Structural values come from `src/config/`, never
from translation files.

### Shared-spring preview

The `/s/{documentId}` Server Component resolves a UI locale and complete BCP 47
language preference from the locale cookie and request headers. It calls the
server-only Spring Preview client, which validates and normalizes Strapi data
into the three renderable outcomes `ok`, `not_found`, and `error`.

### Newsletter signup

The client form invokes a Server Action. The action validates user-controlled
fields, applies process-local abuse protection, adds server-owned consent and
source metadata, and posts to Strapi. The browser never receives a Strapi API
token or calls the backend directly.

The wire contracts and failure semantics for both flows live in
[Strapi integrations](strapi-integrations.md).

## Sources of truth

- User-facing copy: `messages/<locale>.json`, typed by
  `src/i18n/dictionary.ts`.
- Supported locales and URL behavior: `src/i18n/config.ts` and `src/proxy.ts`.
- Store URLs, app identifiers, and canonical site URL: `src/config/site.ts`.
- Asset dimensions and paths: `src/config/assets.ts`.
- Legal document and newsletter consent versions: `src/config/legal.ts`.
- Dependency versions and commands: `package.json`.
- Deployment commands: `nixpacks.toml` and `next.config.ts`.

Documentation should explain why these values matter and how systems interact;
it should link to the source rather than copying change-prone values unless the
value is part of an external contract.
